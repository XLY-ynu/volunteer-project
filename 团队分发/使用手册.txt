          志愿者服务活动中心多媒体展示系统 - 团队开发使用手册

================================================================================
一、环境要求
================================================================================

必需软件：
  - JDK 17 或 21（项目配置为17，兼容21）
  - Node.js 18+
  - MySQL 8.0+
  - Maven 3.8+

开发工具（任选）：
  - IntelliJ IDEA（推荐）
  - VS Code
  - Eclipse

验证环境：
    java -version      # 应显示 17 或 21
    node -v            # 应显示 18.x 或更高
    npm -v             # 应显示 9.x 或更高
    mysql --version    # 应显示 8.x

================================================================================
二、数据库初始化（重要 - 新成员必做）
================================================================================

【方式一】一键初始化（推荐）

Windows 用户：
    1. 双击运行 团队分发/database/init_database.bat
    2. 输入你的 MySQL root 密码
    3. 等待执行完成

命令行方式：
    mysql -u root -p < 团队分发/database/volunteer_complete.sql

【方式二】使用 MySQL Workbench / Navicat

    1. 打开数据库管理工具，连接到 MySQL
    2. 打开文件：团队分发/database/volunteer_complete.sql
    3. 点击执行按钮
    4. 等待执行完成

【验证数据库】执行以下 SQL 确认数据导入成功：

    USE volunteer;
    SELECT COUNT(*) FROM role;            -- 应该返回 4
    SELECT COUNT(*) FROM user;            -- 应该返回 2
    SELECT COUNT(*) FROM menu_category;   -- 应该返回 6
    SELECT COUNT(*) FROM content_item;    -- 应该返回 18
    SELECT COUNT(*) FROM activity;        -- 应该返回 2

================================================================================
三、修改数据库连接配置
================================================================================

编辑文件：backend/src/main/resources/application.yml

找到以下内容，修改密码为你的 MySQL 密码：

    spring:
      datasource:
        url: jdbc:mysql://localhost:3306/volunteer?useUnicode=true&characterEncoding=utf-8&useSSL=false&serverTimezone=Asia/Shanghai
        username: root
        password: 你的MySQL密码    <-- 修改这里

================================================================================
四、后端启动
================================================================================

【使用 IntelliJ IDEA】

1. 打开 IDEA，选择 Open，打开 backend 文件夹
2. 等待 Maven 自动下载依赖（首次可能需要几分钟）
3. 如果提示 JDK 版本，选择 JDK 17 或 21
4. 找到 src/main/java/com/example/volunteer/VolunteerApplication.java
5. 右键点击，选择 Run 'VolunteerApplication'

【使用 VS Code】

1. 安装 Java 扩展包（Extension Pack for Java）
2. 打开 backend 文件夹
3. 按 F5 运行

【使用命令行】

    cd backend
    mvn clean spring-boot:run

后端启动成功后，访问 http://localhost:8080 应该返回 JSON 数据

================================================================================
五、前端启动
================================================================================

【安装依赖】

    cd frontend
    npm install

如果下载慢，先配置镜像：
    npm config set registry https://registry.npmmirror.com
    npm install

【启动开发服务器】

    npm run dev

前端地址：http://localhost:5173

【管理员端】系统管理
    地址：http://localhost:5173/login
    账号：admin / admin123
    功能：用户管理、权限管理、操作日志、系统设置

【志愿者组织端】组织管理
    地址：http://localhost:5173/org/login
    账号：org1 / admin123
    功能：内容管理、媒体管理、活动管理、志愿者审核、求助处理、终端发布

【志愿者端】志愿者服务
    地址：http://localhost:5173/portal
    账号：注册后登录
    功能：内容浏览、媒体观看、活动报名、签到打卡、加入组织

【普通用户端】公众服务
    地址：http://localhost:5173/user-portal
    账号：注册后登录
    功能：内容浏览、媒体观看、发布求助、成为志愿者

角色权限说明：
    ADMIN     - 管理员：系统级管理（用户、权限、日志）
    ORG       - 志愿者组织：业务管理（内容、媒体、活动、志愿者、求助）
    VOLUNTEER - 志愿者：参与服务（浏览、报名、签到）
    USER      - 普通用户：基础服务（浏览、求助）

七、快速体验流程（重要）

以下流程帮助你快速了解系统的完整功能，建议按顺序体验。

--------------------------------------------------------------------------------
【流程一】管理员端 - 系统管理
--------------------------------------------------------------------------------
访问地址：http://localhost:5173/login
测试账号：admin / admin123

步骤1：登录系统
    → 输入账号密码 → 点击登录 → 进入管理后台

步骤2：查看仪表盘
    → 首页显示系统概览
    → 查看用户总数
    → 查看最近操作记录

步骤3：用户管理
    → 点击左侧菜单"用户管理"
    → 查看用户列表（admin、org1 等）
    → 点击"新增用户" → 填写用户名、密码、角色 → 保存
    → 可编辑、删除、启用/禁用用户

步骤4：操作日志
    → 点击左侧菜单"操作日志"
    → 查看所有管理员的操作记录
    → 支持按时间、用户名筛选

步骤5：系统设置
    → 点击左侧菜单"系统设置"
    → 查看系统信息（版本、运行时间等）
    → 可进行系统备份操作

--------------------------------------------------------------------------------
【流程二】组织端 - 内容管理
--------------------------------------------------------------------------------
访问地址：http://localhost:5173/org/login

步骤1：登录组织端

步骤2：查看工作台

================================================================================
十一、常见问题解决
================================================================================

【问题1】Maven 下载依赖很慢

解决：配置阿里云镜像
在用户目录下创建或编辑 .m2/settings.xml：

    <settings>
      <mirrors>
        <mirror>
          <id>aliyun</id>
          <mirrorOf>central</mirrorOf>
          <url>https://maven.aliyun.com/repository/central</url>
        </mirror>
      </mirrors>
    </settings>

--------------------------------------------------------------------------------

【问题2】IDEA 提示 JDK 版本不对

解决：
    File -> Project Structure -> Project SDK -> 选择 JDK 17 或 21
    File -> Settings -> Build -> Compiler -> Java Compiler -> Target bytecode version -> 17

--------------------------------------------------------------------------------

【问题3】端口被占用

后端 8080 端口：修改 application.yml 中的 server.port
前端 5173 端口：修改 vite.config.ts 中的 server.port

查看端口占用：
    Windows: netstat -ano | findstr :8080
    杀死进程: taskkill /PID <进程ID> /F

--------------------------------------------------------------------------------

【问题4】数据库连接失败

检查：
    1. MySQL 服务是否启动
       Windows: services.msc 查看 MySQL 服务状态
    2. 用户名密码是否正确
    3. 数据库 volunteer 是否已创建
    4. application.yml 中的密码是否正确

--------------------------------------------------------------------------------

【问题5】前端编译报错

解决：删除 node_modules 重新安装
    Windows: rmdir /s /q node_modules
    然后: npm install

如果还是报错，尝试清除缓存：
    npm cache clean --force
    npm install

--------------------------------------------------------------------------------

【问题6】登录后台提示"用户名或密码错误"

检查：
    1. 确认已执行 volunteer_complete.sql 导入数据
    2. 默认账号：admin  密码：admin123
    3. 组织端账号：org1  密码：admin123

--------------------------------------------------------------------------------

【问题7】上传文件失败

检查：
    1. backend/uploads 目录是否存在
    2. 目录是否有写入权限
    3. 文件大小是否超过限制（默认10MB）

--------------------------------------------------------------------------------

【问题8】npm install 报错 EACCES 权限问题

解决（Windows）：
    以管理员身份运行命令提示符
    或者修改 npm 全局目录权限
